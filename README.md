# 宝肤语品牌内容伙伴计划

这是一个“先打通业务闭环”的可运行 MVP，包含用户端、任务中心和运营后台。

## 已实现的核心逻辑

- 报名：姓名、手机号、自媒体平台、主页链接、邀请码
- 报名审核：运营人员通过或拒绝，审核通过后生成成员和专属邀请码
- 每日任务：每位成员每天只能领取一次同一任务
- 作品提交：提交公开作品链接，等待运营审核
- 任务积分：作品审核通过后自动增加 3 积分
- 推荐积分：被推荐人首条有效作品审核通过后，推荐人自动增加 1 积分；只奖励一次
- 积分台账：所有增加、冻结和退回都保留独立记录
- 积分兑换：最低 10 积分；提交时先冻结，拒绝后自动退回，避免重复兑换
- 运营后台：审核报名、作品和兑换，查看积分台账

## 本地运行

```bash
npm install
npm run dev
```

主要入口：

- 活动首页：`#/`
- 用户任务中心：`#/task-center`
- 运营后台：`#/admin`

当前默认使用浏览器 `localStorage` 作为演示数据库，方便在没有云服务账号时完整验证流程。运营后台点击“重置演示数据”可以恢复初始状态。

`.env` 中的 `VITE_DATA_MODE` 默认保持为 `demo`。只有在前端云数据适配器全部接通后，才改成 `supabase`，避免演示数据与正式数据混用。

## 验证完整闭环

1. 打开 `#/admin`，通过待审核报名。
2. 通过预置的待审核作品；邀请人会获得 1 积分，被邀请人获得 3 积分。
3. 打开 `#/task-center`，领取今日任务并提交作品链接。
4. 回到 `#/admin`，审核刚提交的作品，用户端积分实时更新。
5. 用户端申请积分兑换，再到后台确认打款或退回积分。

## 正式数据库

[`supabase/migrations/202608010001_partner_program.sql`](supabase/migrations/202608010001_partner_program.sql) 已包含正式数据模型：

- `applications`、`members`、`tasks`
- `task_claims`、`submissions`
- `ledger_entries`、`redemptions`
- 行级权限（RLS）
- 报名、绑定手机号用户、领取任务、提交作品、审核、积分奖励与兑换 RPC
- 并发兑换锁、唯一奖励约束和待审数据索引

正式上线前还需要：

1. 创建 Supabase 项目并执行迁移。
2. 开通手机号 OTP 登录并配置短信服务。
3. 将运营人员的 Supabase 用户 ID 写入 `staff_users`。
4. 接入前端云数据适配器和验证码/限流服务。
5. 替换公司主体、企业微信、隐私说明和结算规则。

请勿把 `service_role` 密钥放进前端或提交到 GitHub。

## GitHub Pages

仓库内置 Pages 部署工作流。推送到 GitHub 后，在仓库设置中将 Pages Source 设为 **GitHub Actions**。以后购买域名，可在 Pages 设置里绑定自定义域名并配置 DNS。

## 当前边界

这是业务逻辑 MVP，不是最终品牌视觉版本。项目没有使用已被否决的人物图，后续可以在不改业务逻辑的情况下单独重做页面美术。
